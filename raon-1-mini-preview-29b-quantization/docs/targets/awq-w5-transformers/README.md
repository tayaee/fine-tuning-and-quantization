Historical timing evidence: [observed wall-clock durations](timing-log.md).

## Goal

Quantize the MoE expert weights of `KRAFTON/Raon-1-mini-preview` to W5A16 and produce a
`pack-quantized` checkpoint that can be loaded by `transformers`. Five-bit quantization
usually degrades quality less than three-bit quantization, but it also provides less
compression and has a narrower set of supported runtime and hardware combinations.

| Property | Value |
|---|---|
| Target ID | `awq-w5-transformers` |
| Runtime | `transformers` + `compressed-tensors` |
| Storage format | `pack-quantized` |
| Weight recipe | GPTQ W5A16, asymmetric, group size 64 |
| AWQ smoothing | Optional; default is `RQ_AWQ_FIRST=0` |
| Quantization scope | MoE experts only (`gate_proj`, `up_proj`, `down_proj`) |
| Kept in BF16 | Router, attention, shared experts, dense layer 0, LM head |
| Full calibration | 256 samples, sequence length 2048 |
| Checkpoint size | 20.0–35.0 GB |

> **Name versus default recipe:** AWQ replay is currently incompatible with Raon's
> `RoutedLinear` implementation and fails deterministically. The default recipe therefore
> applies GPTQ W5 without AWQ smoothing. The target ID and output format remain
> `awq-w5-transformers` for compatibility with the original plan. To experiment with AWQ
> first, explicitly set `RQ_AWQ_FIRST=1`; the script falls back to pure GPTQ if that
> recipe fails.

## Prerequisites

- Run all commands from the repository root.
- The base model is gated, so Hugging Face authentication is required.
- `$RQ_SHARED` must have enough space for the BF16 base and the quantized output.
- The `smoke` and `full` scripts include environment synchronization and calibration
  generation, but the first run still requires access to the base model and adequate GPU
  and disk capacity.

## Recommended procedure: smoke → full → upload → customer acceptance

### 1. Run the smoke pipeline

```bash
./run-s1-to-s4-smoke-awq-w5-transformers.sh
```

The wrapper runs these stages in order:

1. `s1-00-setup-environment.sh` — synchronize the environment
2. `s1-05-setup-acceptance-criteria.sh` — validate the acceptance contract
3. `s1-10-prep-calibration.sh` — generate calibration data
4. `s1-15-preflight-check.sh` — check GPU and library compatibility
5. `s2-00-dequant-mxfp8-into-bf16.sh` — restore the shared MXFP8 → BF16 base
6. [`s3-05-quant-awq-w5-transformers.sh`](../../../s3-05-quant-awq-w5-transformers.sh) —
   quantize to W5
7. `gate-quant` — validate `pack-quantized`, packed tensors, and custom code
8. `s4-00-measure-ppl__transformers-only.sh` — measure PPL against the base and run
   `gate-ppl`
9. Run GSM8K, KMMLU, and format-compliance evaluations and their gates
10. Run the serving benchmark, generate the model card, and complete the pre-upload audit
    (`gate-release`)

### 2. Run the full pipeline

```bash
./run-s1-to-s4-full-awq-w5-transformers.sh
```

The full build uses 256 calibration samples and sequence length 2048. Existing common
artifacts are reused through freshness stamps, so this command does not restore the BF16
base from scratch again.

To force recalculation, use:

```bash
FORCE=1 ./run-s1-to-s4-full-awq-w5-transformers.sh
```

### 3. Run individual stages manually

Use these commands only when the complete wrapper does not fit the target's workflow.

```bash
./s3-05-quant-awq-w5-transformers.sh full
./s4-00-measure-ppl__transformers-only.sh full base,awq-w5-transformers
./s4-05-prep-gsm8k.sh full
./s4-25-prep-kmmluko.sh full
./s4-35-check-format__transformers_vllm_both.sh full --prepare
./s4-10-answer-benchmarks-base__transformers-only.sh full
./s4-15-answer-benchmarks-quantized__transformers-only.sh full awq-w5-transformers
./s4-20-aggregate-gsm8k__transformers_vllm_both.sh full
./s4-30-score-kmmluko__transformers_vllm_both.sh full
./s4-35-check-format__transformers_vllm_both.sh full
```

### 4. Upload to the Hub

```bash
./s5-00-upload-to-hf.sh full awq-w5-transformers
```

Before upload, the model card generated by `s4-70-update-readme.sh` and the audit performed
by `s4-75-verify-upload.sh` must both pass. If other targets are uploaded together, wait
until this target's release gate has passed and then use `all` explicitly.

### 5. Run Transformers customer acceptance

```bash
./s6-00-clean-serving-workspace.sh full
./s6-10-verify-readme-with-awq-w5-transformers-and-transformers.sh full
```

This test executes the Hub README's `Usage - transformers` block **verbatim** and verifies
that it produces a non-empty chat response. The result is recorded in
`$RQ_SHARED/outputs/s6-full/awq-w5-transformers.json`.

## Acceptance criteria

The single source of truth is
[`config/acceptance.toml`](../../../config/acceptance.toml).

| Check | Criterion |
|---|---|
| Compression format | `pack-quantized` |
| Checkpoint size | 20.0–35.0 GB |
| PPL | Accept when the delta from the base is `< 0.3`; Conditional when it is `< 1.0`; otherwise Discard |
| GSM8K | Accuracy drop from the base `<= 0.02` |
| KMMLU | Accuracy drop from the base `<= 0.03` |
| Instruction and format compliance | Pass rate `>= 0.90` |
| Release | Model card and pre-upload audit pass |

## Troubleshooting

- **`format != pack-quantized` or a dense fallback**: the experts were not actually
  compressed. The immediate `gate-quant` failure is intentional. Check the custom module's
  `can_compress` implementation and the calibration shim.
- **Five-bit runtime compatibility error**: compare the `transformers`,
  `compressed-tensors`, and accelerator versions with the versions required by the model
  card, and ensure `trust_remote_code` is enabled.
- **AWQ replay error**: use the default pure-GPTQ path. `RQ_AWQ_FIRST=1` is experimental.
- **Gates pass but the response is empty**: compare the `s6` logs with the dependency
  versions in the model card. Customer acceptance fails if the published card has drifted
  from the source snippet.
